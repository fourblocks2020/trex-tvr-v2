# snapshot-only execution ownership 경계

## Criterion

TVR decision runtime은 다음 core slot snapshot만 execution-state 입력으로 소비해야 한다. KIS failure, broker rejection reason, broker attempt identity, retryability, timeout과 fill/cancel raw event를 wire, strategy input 또는 durable retry state로 소비·저장해서는 안 된다. core가 sell failure를 holding으로 수렴하거나 unknown submission을 reconciliation하는 동안 TVR은 별도 outcome wire나 automatic retry branch를 가져서는 안 된다.

## Verification

- 성공 조건: `build_daemon()`이 broker/fill event consumer를 생성·연결하지 않고 decision cycle이 event port를 poll하지 않으며, injected raising EventsPort가 호출되지 않는다.
- 실패 조건: retryability/attempt/failure event에 따라 intent를 재제출하거나 durable attempt counter/queue를 유지하거나 raw broker outcome을 strategy에 전달하면 FAIL이다.
- transport reconnect/backoff는 broker order retry가 아니라 messaging connection recovery임을 구분한다.
- 현재 평가: current local implementation과 no-poll/no-wiring regressions로 satisfied됐다. legacy event API는 import compatibility surface로만 남아 있다.
- 검사 방법: `tests/runtime/test_daemon_cycle.py`, build-daemon source inspection, runtime search for `retryable`, broker attempt/failure와 `poll_events`를 수행한다.
