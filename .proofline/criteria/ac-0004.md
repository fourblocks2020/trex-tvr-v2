# sell decision 멱등성과 독립 후속 판단

## Criterion

동일한 TVR sell decision을 transport 수준에서 중복 전송할 때는 동일 intent ID를 사용해야 한다. core가 새 broker attempt 없이 slot을 holding으로 수렴한 뒤 TVR이 이후 core snapshot을 받아 수행하는 독립 정상 전략 decision은 이전 decision과 다른 intent ID를 사용해야 한다. 새 ID를 위한 decision identity는 current snapshot decision cycle에서 도출하고 broker rejection, retryability 또는 attempt identity에서 도출해서는 안 된다.

## Verification

- 성공 조건: 동일 strategy·instance·date·slot·decision token은 동일 ID이고, 이후 snapshot cycle의 다른 decision token은 다른 ID다. 연속 holding snapshots에서 broker event injection 없이 독립 sell IDs가 생성된다.
- 실패 조건: 하루 동안 같은 sell ID만 재사용해 core dedup으로 영구 차단되거나, broker retry metadata를 ID에 포함하거나, 한 decision의 transport retry가 새 ID를 만들면 FAIL이다.
- current cadence의 독립 strategy decisions가 빈번해질 수 있으므로 core slot state gate와 strategy rebalance condition을 함께 회귀 검증한다.
- 현재 평가: current local implementation과 focused regression으로 satisfied됐다.
- 검사 방법: `tests/runtime/test_intent_builder.py`, `tests/runtime/test_daemon_cycle.py`, `tests/runtime/test_daemon_fanin.py`에서 same-decision/different-cycle ID와 submitted payload를 단언한다.
