# tag-only publication과 version identity

## Criterion

Registry publication은 strict stable `refs/tags/vX.Y.Z` push에서만 허용되어야 하고 branch/main/PR/manual verification은 registry write와 분리돼야 한다. Event/ref, exact checkout, Git tag, project version, runtime version과 OCI version은 registry login 또는 image push 전에 exact match해야 한다.

## Verification

- 성공 조건: publication workflow trigger는 stable tag push만 허용하고 publish job에만 job-scoped `packages: write`가 있다. Verification workflow에는 registry token, login, push와 write permission이 없다.
- 성공 조건: malformed/pre-release tag, non-tag event, checkout mismatch 또는 tag/project/runtime/OCI version mismatch가 image build 또는 registry login 전에 fail-closed한다.
- 실패 조건: branch/main이 registry write를 수행하거나 `latest`를 만들거나 version mismatch 상태에서 publication path가 진행되면 FAIL이다.
- 현재 평가: workflow/helper contract tests가 strict gate, no-write verification, exact version validation과 no-latest를 검증했고 focused suite가 PASS하여 satisfied다. 실제 tag 생성·push와 publication은 수행하지 않았다.
- 검사 방법: `.github/workflows/publish-image.yml`, `verify-container.yml`, `scripts/image_release.py`의 trigger/permission/command ordering을 검사하고 release tests를 실행한다.
