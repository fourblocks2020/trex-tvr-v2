# build-once provenance와 secret exclusion

## Criterion

Verify job은 exact source image를 한 번만 build하고 검증한 동일 image를 archive로 publish job에 전달해야 한다. Publish job은 rebuild 없이 archive SHA-256, image ID, OCI revision/version을 확인하고 SHA12/version selector의 registry digest가 동일함을 입증해야 한다. Synthetic secret canary는 build context, image와 전달 artifact/output 어디에도 남아서는 안 된다.

## Verification

- 성공 조건: verify job에 image build가 정확히 한 번 존재하고 `docker save`, SHA-256, image ID와 helper artifact가 전달된다. Publish job에는 build 명령이 없고 checksum·image ID·OCI label 검증 뒤 login/push가 일어난다.
- 성공 조건: image config/history/filesystem, archive listing/content, metadata와 helper output의 canary scan이 PASS한다. Registry token은 `--password-stdin`으로만 전달한다.
- 성공 조건: SHA12와 version selector push 결과 digest가 동일하고 immutable digest가 evidence에 기록되며 `latest`는 생성하지 않는다.
- 실패 조건: publish-side rebuild, source/image/archive identity mismatch, canary 발견, token argv 노출 또는 selector digest 불일치가 있으면 FAIL이다.
- 현재 평가: release tests와 실제 archive scan/image ID/checksum evidence가 PASS했고 no-rebuild workflow가 확인되어 repository-local 범위에서 satisfied다. Registry digest는 미게시이므로 live evidence가 아니라 fail-closed contract로만 구현됐다.
- 검사 방법: workflow contract tests, helper unit tests, actual `docker save`와 `image_release.py scan/inspect-image/checksum`을 실행하고 publication 시 두 remote digest를 read-back한다.
