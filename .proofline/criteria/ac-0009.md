# 격리 dependency startup와 initial status smoke

## Criterion

Publication smoke는 internal Docker network의 digest-pinned RabbitMQ·Redis와 synthetic fake kis-data-hub를 사용해 AMQP login, Redis ping, kis-data-hub `/health`, TVR non-root/read-only `build_daemon()` startup과 initial `started` status snapshot까지만 검증해야 한다. Strategy decision, core RPC, account/order side effect는 실행하거나 보장하지 않아야 한다.

## Verification

- 성공 조건: RabbitMQ와 Redis input은 digest로 고정되고 fake kis-data-hub만 synthetic local response를 제공한다. Dependency readiness 뒤 TVR container가 read-only, capabilities drop, no-new-privileges, user `10001:10001`로 실행된다.
- 성공 조건: config와 secret은 read-only mount, status는 별도 writable mount이며 initial status의 state가 `started`다.
- 성공 조건: startup·timeout·cleanup 실패가 fail-closed하고 성공·실패 모두 container/network cleanup을 수행한다.
- 실패 조건: dependency readiness 없이 성공하거나 `run_forever`, decision cycle, trex-core slot/intent RPC, KIS query, intent delivery, account access 또는 실제 주문을 실행하면 FAIL이다.
- 현재 평가: actual isolated startup smoke와 initial status가 PASS했고 helper cleanup 후 잔여 container/network/image가 없었으며 tests가 failure/timeout cleanup을 검증해 satisfied다.
- 검사 방법: `image_release.py smoke --image ...`, focused helper tests와 Docker resource read-back을 수행한다.
