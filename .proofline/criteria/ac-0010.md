# non-root read-only 운영과 rollback 경계

## Criterion

Runtime과 운영 문서는 non-root `10001:10001`, read-only root filesystem, config·secret·status mount 분리, capability drop와 no-new-privileges를 요구해야 한다. 운영 rollout과 rollback은 immutable GHCR digest를 기준으로 하며 기존 Git tag를 삭제·재생성하지 않고 bounded operator stop과 외부 state 비rollback 경계를 명시해야 한다.

## Verification

- 성공 조건: Docker image default user와 workflow smoke security options가 criterion과 일치하고 status writable mount를 제외한 application root가 read-only다.
- 성공 조건: 운영 문서가 digest pull/run/rollback, config·secret/status mount, status snapshot, `docker stop --time 30`, 기존 tag 비재생과 RabbitMQ·Redis·broker/order state 비rollback을 설명한다.
- 실패 조건: root runtime, writable root, secret bake-in, mutable selector만을 rollback authority로 사용하거나 publication을 production readiness/deployment 완료로 주장하면 FAIL이다.
- 현재 평가: image inspect와 actual smoke에서 user/security/mount가 PASS했고 `docs/container-operations.md`가 운영 경계를 소유하여 satisfied다.
- 검사 방법: Dockerfile/workflow contract tests, `docker image inspect`, actual read-only run과 operations document assertion을 실행한다.
