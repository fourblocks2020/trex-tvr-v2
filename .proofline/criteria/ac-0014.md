# Idle heartbeat와 bounded reconnect 상태 복구

## Criterion

Daemon은 cadence remainder 동안 단순 sleep 대신 BlockingConnection AMQP I/O를 반복 처리하여 negotiated heartbeat를 유지하고 poll interval 바닥을 보존해야 한다. Idle/reset/restart transport failure 뒤 기존 exponential backoff 경계에서 stale connection/channel을 정리하고 reconnect하며 정상 cycle 뒤 RabbitMQ dependency 상태와 last error를 회복해야 한다.

## Verification

- 성공 조건: Idle wait가 event pump 조기 반환에도 전체 cadence remainder를 보존하고, heartbeat 30초보다 긴 35초 idle 뒤 RPC가 성공하며 broker restart 뒤 reconnect가 성공한다.
- 실패·경계 조건: Stale stream의 graceful close가 실패해도 reconnect cleanup을 막지 않는다. Transport failure는 무한 busy retry가 아니라 기존 1~30초 bounded backoff를 따른다.
- 검사 방법: Cadence·connection 단위 테스트와 `TVR_TEST_RABBITMQ_URL`/`TVR_TEST_RABBITMQ_CONTAINER`를 사용한 disposable RabbitMQ integration을 실행한다.
