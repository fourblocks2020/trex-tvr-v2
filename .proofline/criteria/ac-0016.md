# 실제 RabbitMQ 장애 주입 및 secret-safe 회귀 검증

## Criterion

Transport resilience 변경은 unit regression과 disposable RabbitMQ 장애 주입을 모두 통과해야 한다. 실제 AMQP 경로에서 confirm/direct reply-to, heartbeat보다 긴 idle, reconnect 및 broker restart를 검증하고 daemon 경계에서 buy/sell ambiguous outcome의 no-duplicate convergence를 검증해야 한다. Test·문서·오류에는 실제 credential, token 또는 connection string을 보존하지 않아야 한다.

## Verification

- 성공 조건: 전체 회귀와 focused test가 통과하고 disposable RabbitMQ integration에서 35초 idle 및 실제 container restart 후 reconnect가 통과하며 resource가 정리된다.
- 실패·경계 조건: Mock-only 결과로 broker restart를 대체하지 않는다. Integration 환경이 명시되지 않은 일반 full suite에서는 infra test를 skip할 수 있으나 실제 완료 evidence에는 별도 실행 PASS가 있어야 한다.
- 검사 방법: `.venv/bin/python -m pytest -q`, changed-scope Ruff, `git diff --check`, `uv build`, disposable RabbitMQ integration 및 독립 QC evidence를 확인한다.
