# TVR snapshot-only 재제출·세션 경계

## Problem

TVR의 기존 sell intent ID는 동일 strategy·instance·trading date·slot에서 하루 동안 재사용되었다. core가 sell 미수락·미체결을 확인해 slot을 `holding`으로 수렴시킨 뒤에도 TVR이 같은 ID를 다시 제출하면 core intent dedup에 걸려 이후 정상 전략 판단이 독립 intent로 admission되지 않는 문제가 있었다.

이 문제를 broker retryability wire나 TVR durable retry state로 해결하면 execution ownership이 TVR로 새어 나온다. TVR은 KIS failure, broker rejection reason, broker attempt identity, retryability, timeout, 체결·취소 raw event를 수신·소비하지 않고 다음 core slot snapshot만으로 전략 판단해야 한다. core는 execution 결과 기록·reconciliation·state convergence를 소유하고 자동 broker retry를 판단하거나 수행하지 않는다.

동시에 모든 buy/sell intent 생성은 KST session과 slot `markets` eligibility를 따라야 한다. NXT-only 구간에서 NXT가 없는 slot을 주문하거나 경매 공백·장외·휴장일에 RPC를 호출해서는 안 된다. TVR intent는 venue를 지정하지 않고 core #61의 omitted venue→SOR 계약을 사용해야 한다.

- 승인된 issue 본문은 `08:50:00 <= t < 09:00:30`, `15:20:00 <= t < 15:30:00`을 경매 공백으로 정의하고 buy/sell suppress를 요구한다.

## Scope

- TVR은 모든 buy/sell intent 생성 전에 session eligibility를 판정한다.
- NXT-only 구간은 승인 원문대로 `08:00:00 <= t < 08:50:00` 및 `15:30:00 <= t <= 20:00:00`이다.
- NXT-only 구간에서 slot `markets`가 누락·빈 배열이거나 NXT를 포함하지 않으면 buy/sell RPC를 만들거나 호출하지 않고 `market_not_eligible` diagnostic을 남긴다.
- KRX main 구간의 eligible slot과 NXT-only eligible slot은 정상 전략 평가를 수행할 수 있다.
- `08:50:00 <= t < 09:00:30`, `15:20:00 <= t < 15:30:00`, out-of-session과 확인된 휴장일에는 buy/sell RPC를 만들거나 호출하지 않는다.
- TVR buy/sell intent는 `venue`를 보내지 않는다. core #61은 omitted venue를 SOR로 정규화한다.
- TVR은 KIS failure, broker rejection detail, broker attempt identity, retryability, timeout, fill/cancel raw event를 전략 입력이나 durable retry state로 소비·저장하지 않는다.
- core는 no-auto-retry execution convergence와 reconciliation을 소유한다. TVR은 다음 core slot snapshot의 상태만으로 새 정상 전략 decision을 수행한다.
- 동일 sell decision의 transport duplicate는 같은 ID를 사용하고 이후 snapshot cycle의 독립 decision은 다른 ID를 사용한다. ID의 새 decision token은 broker outcome에서 파생하지 않는다.
- core #60 no-auto-retry 및 core #61 omitted venue→SOR와 cross-repository wire compatibility, import seam과 TVR regression을 검증한다.
- current implementation evidence와 승인 criterion의 차이를 AC별로 명시하며, active AC status 자체를 구현 완료 claim으로 사용하지 않는다.

- push, PR, remote main integration, image publication, deployment, release 또는 issue closure
- ProofLine delivery/release lifecycle closure의 소급 주장

## Risks and Unknowns

### Risks

- 승인 원문의 `20:00:00 포함`과 현재 implementation/QC의 `20:00:00 제외`가 충돌한다. 이 Discovery와 AC는 승인 원문을 scope authority로 유지하며 current implementation을 해당 boundary에서 미충족으로 평가한다.
- holiday cache/API 장애는 기존 fail-open 정책이므로 확인된 휴장일은 차단하지만 조회 실패일은 거래일로 간주될 수 있다.
- legacy EventsPort/parser/consumer가 runtime에 연결되지는 않지만 compatibility surface로 남아 있어 향후 오연결 방지 regression이 필요하다.
- sell decision ID가 cycle timestamp를 포함하므로 매 cycle의 정상 전략 판단은 독립 intent가 될 수 있다. broker 자동 retry가 아니지만 전략 cadence와 core slot state gate가 주문 빈도 안전성을 유지해야 한다.
