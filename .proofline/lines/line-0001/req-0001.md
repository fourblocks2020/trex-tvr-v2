# TVR snapshot-only 재제출·세션 경계

## Objective

TVR의 모든 buy/sell intent admission을 승인된 KST session과 slot `markets` 계약에 맞추고, strategy intent의 venue를 생략하여 core의 SOR routing contract를 사용한다. TVR은 broker outcome이나 retryability가 아니라 다음 core slot snapshot만으로 정상 전략 판단을 수행한다. 동일 sell decision은 멱등으로 유지하되 이후 holding snapshot의 독립 decision은 새 intent가 되게 해 기존 하루 단위 sell ID 재사용으로 인한 영구 dedup 문제를 제거한다.

## Scope

- NXT-only는 `08:00:00 <= t < 08:50:00` 및 승인 issue 원문에 따라 `15:30:00 <= t <= 20:00:00`이다.
- NXT-only에서 slot `markets`가 누락·빈 배열이거나 NXT를 포함하지 않으면 buy/sell RPC를 만들거나 호출하지 않고 diagnostic을 남긴다.
- `08:50:00 <= t < 09:00:30`, `15:20:00 <= t < 15:30:00`, out-of-session과 확인된 휴장일에는 buy/sell RPC를 만들거나 호출하지 않는다.
- KRX main 및 NXT-only eligible slot의 buy/sell intent는 `venue` 없이 core에 전달될 수 있고 core #61은 omitted venue를 SOR로 정규화한다.
- TVR runtime은 KIS failure, broker rejection reason, attempt identity, retryability, timeout, fill/cancel raw event를 wire나 strategy state로 소비하지 않는다.
- core는 no-auto-retry state convergence와 unknown submission reconciliation을 소유하고 TVR은 다음 core slot snapshot만 소비한다.
- 동일 snapshot decision의 sell intent transport duplicate는 같은 ID를 사용하고, 이후 snapshot cycle에서 수행되는 정상 전략 decision은 broker outcome과 무관한 새 ID를 사용한다.
- core #60 no-auto-retry, core #61 omitted venue→SOR, import seam과 TVR focused/full regression을 검증한다.
- 구현 진행·완료 GitHub comment는 정식 lifecycle artifact가 아닌 repository-local evidence snapshot으로 보존한다.

## Constraints

- issue #5의 승인된 본문과 revisioned 결정이 scope authority다. 구현 결과가 다르면 criterion을 구현에 맞춰 재정의하지 않고 gap으로 기록한다.
- TVR에 broker outcome subscription, automatic retry branch, attempt counter 또는 durable retry queue/state를 추가하지 않는다.
- strategy intent에서 KRX/NXT/SOR를 명시하지 않는다.
- credential, token, DSN, KIS raw secret-bearing payload를 문서 evidence에 기록하지 않는다.
- pre-existing `.stagepilot/`·`.worktrees/` artifact를 이 Line의 source/evidence로 채택하거나 정리하지 않는다.
- Normative Design Documents: 없음. 이 REQ와 AC-0001~AC-0005가 normative specification을 소유한다.
