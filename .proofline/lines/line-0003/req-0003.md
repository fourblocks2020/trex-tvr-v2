# RabbitMQ Transport Reliability / Resilience

## Objective

TVR이 slot snapshot 및 intent admission RPC를 장시간 idle, TCP reset, RabbitMQ restart와 reply 유실 상황에서도 안전하게 운용하도록 한다. Connection tuning과 publisher confirm을 명시적으로 소유하되 broker acceptance와 core admission·execution을 분리하고, ambiguous intent outcome에서는 신규 주문을 만들지 않은 채 authoritative core slot snapshot으로 수렴한다.

## Scope

- Typed RabbitMQ connection profile은 heartbeat 30초, blocked connection timeout 30초, socket timeout 10초를 기본값으로 제공하고 양의 정수 override만 허용한다.
- Application-owned tuning key가 RabbitMQ URL query에도 있으면 이중 authority로 보고 startup을 fail-closed한다.
- Slot 및 intent RPC의 공용 publish 경로에서 publisher confirm을 사용하고 Nack·AMQP reset·RPC timeout을 구분된 transport failure로 다룬다.
- Daemon cadence idle wait는 AMQP event loop를 지속적으로 처리하면서 poll interval 바닥을 보존한다.
- Reset/timeout 후 bounded backoff와 reconnect를 수행하고 다음 cycle은 authoritative slot snapshot 조회부터 시작한다.
- Intent admission reply가 유실될 수 있는 ambiguous outcome에서는 same/fresh intent의 daemon-local 재전송을 추가하지 않는다.
- Unit test 및 disposable RabbitMQ로 confirm, 35초 idle, graceful/stale reconnect, actual broker restart와 buy/sell no-duplicate convergence를 검증한다.
- GitHub 구현 진행·완료 comment를 비정식 repository-local evidence snapshot으로 보존한다.

## Constraints

- GitHub issue #6의 APPROVED 본문과 OQ-1-A~OQ-7-A가 scope authority다.
- TVR은 broker outcome, order execution, durable admission/dedup, fill reconciliation 또는 slot recovery lifecycle을 소유하지 않는다.
- Credential, token, password와 RabbitMQ connection string 실제 값은 source, test evidence, status 및 문서에 기록하지 않는다.
- Normative Design Documents: 없음. 이 REQ와 AC-0012~AC-0016이 normative specification을 소유한다.
