# buy를 decision-scoped 멱등 ID로 전환

## Objective

TVR buy intent가 동일 strategy decision의 transport 중복에는 하나의 멱등 identity를 유지하고, 이후 authoritative core slot snapshot에서 발생한 독립 decision에는 새 identity를 사용하도록 한다. 프로세스·거래일 단위 local admission 이력 대신 최신 snapshot lifecycle과 현재 전략 조건만으로 후속 buy 가능 여부를 판단해, 거절 또는 주문 완료 뒤 안전하게 재평가하면서도 ambiguous outcome의 중복 주문을 방지한다.

## Scope

- Buy intent ID를 `buy:{strategy}:{instance}:{date}:{slot}:{decision_at}` 형식으로 생성하고 `decision_at`을 필수 strategy decision-cycle identity로 취급한다.
- 동일 decision payload의 transport 중복은 동일 `intent_id`를 유지하고, 이후 새 authoritative snapshot을 평가한 독립 decision은 같은 거래일·같은 slot에서도 다른 `intent_id`를 사용한다.
- `buy:`와 `sell:` 방향 namespace를 유지하고 RabbitMQ request의 `correlation_id`를 payload `intent_id`와 동일하게 유지한다.
- Buy payload builder는 `decision_at`이 없으면 fail-fast하고, ID 생성에 broker result, retryability 또는 attempt identity를 사용하지 않는다.
- 프로세스 수명 또는 거래일 동안 `(instance, slot)`을 차단하는 `_admitted_slots`, tracker와 `reentry_skip` 동작을 제거한다.
- `pending_buy`·`pending_sell` snapshot에서는 신규 buy intent를 만들지 않는다. 이후 `holding` snapshot에서는 최신 수량·현금·가격·전략 비중을 다시 계산하고 현재 buy 조건을 만족할 때만 새 decision ID와 buy RPC를 만든다.
- 최초 buy가 `reconcile_warned` 등 pre-broker 사유로 거절된 뒤 경고가 해제된 `holding` snapshot을 받으면 과거 rejection 자체로 차단하지 않고 현재 조건에 따라 독립 재평가한다.
- Reply 유실, timeout 또는 reset의 ambiguous outcome에서는 fresh `decision_at`으로 daemon-local blind retry하지 않고 reconnect 후 authoritative core slot snapshot을 먼저 조회한다.
- Buy builder, daemon cycle, transport wire·`correlation_id`, import seam, 기존 sell behavior와 전체 TVR 회귀를 검증하고 현재 buy slot/day 설명을 decision-scoped 계약으로 갱신한다.

## Constraints

- Confirmed Discovery `dcy-0004`와 GitHub issue #12의 결정된 ID 형식·범위·수용 기준이 scope authority다.
- `decision_at`은 broker outcome이나 transport attempt가 아니라 현재 authoritative core slot snapshot을 평가하는 strategy decision cycle에서 생성한다.
- 동일 decision의 transport duplicate가 같은 ID를 사용한다는 계약은 ambiguous outcome에서 daemon-local 재전송을 새로 허용하지 않는다. `ac-0015`의 snapshot-first 수렴이 우선한다.
- `trex-core`는 `intent_id`를 opaque idempotency key로 계속 처리하며 core PK, DB schema, dedup, admission wire schema, slot lifecycle과 기존 `intent_log` 행을 변경하지 않는다.
- 기존 `ac-0003`의 snapshot-only execution ownership과 `ac-0015`의 ambiguous outcome 무중복 수렴 의미를 변경하지 않고 satisfy한다.
- 기존 `ac-0004`의 sell ID 형식, fail-fast, 동일 decision 안정성 및 후속 snapshot 독립 판단을 변경하지 않는다.
- 새 ID 형식과 old-format ID가 공존할 수 있으므로 기본 cutover 경계는 다음 거래일 시작 전이다. 장중 전환 가능성을 주장하려면 old-format buy intent, 현재 slot lifecycle, pending order와 broker lifecycle을 먼저 감사할 수 있어야 한다.
- Credential, token, connection string과 민감한 운영 식별자는 source, test evidence와 문서에 기록하지 않는다.
- Normative Design Documents: 없음. 이 REQ, `ac-0018`, 기존 `ac-0003`과 `ac-0015`가 normative specification을 소유한다.

## Non-Goals

- `trex-core`의 intent PK, dedup, admission contract, DB schema 또는 broker/slot lifecycle 변경
- 기존 core `intent_log` 행의 삭제·수정·재평가
- Broker 자동 retry, broker failure/retryability event 구독, attempt identity 또는 durable retry state 추가
- 기존 sell decision-scoped identity와 snapshot-only 계약의 변경
- 운영 배포, 장중 cutover 실행, production 설정 변경 또는 실제 주문
- Git push, PR, artifact publication, release 또는 rollout 완료 claim
