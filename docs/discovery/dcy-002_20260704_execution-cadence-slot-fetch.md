# 4. 이번에 정의할 변경

- **세션 윈도우 (사장님 확정)**: 데몬 스케줄 08:00~20:00. 단 **"평가 가능"과 "체결 가능"을 분리** — 세션 캘린더(NXT 프리마켓/정규장/애프터마켓 구간·휴장)를 데몬이 인지하고, 주문은 체결 가능 세션에서만 발신(불가 구간은 평가만/HOLD).
- **폴링 케이던스**: 고정 poll_interval **60s**(config). cycle 소요 ≥ interval 시 **무슬립 드레인**(즉시 다음 cycle), 유휴 시 60s 바닥(busy-loop 방지 하한).
- **다중 인스턴스 팬-인 (사장님 확정, v1 포함)**: config에 인스턴스 목록(`instances = ["longterm", ...]`). cycle마다 각 인스턴스 `trex.slots.req`(strategy:"tvr_v1")를 수집·병합(row에 출처 인스턴스 태깅), intent는 **출처 인스턴스의 intent 큐로 라우팅**. 부분 장애 시 해당 인스턴스만 degraded(다른 인스턴스 계속), 멱등 intent_id에 인스턴스 구분 포함.
- **NXT 지원 (전 스택 신규 — 타 repo REQ)**:
	- trex-core KIS 브로커: 주문에 거래소구분(KRX/NXT/SOR) 지원 — KIS 스펙 조사 후 방식 확정(SOR 위임이 유력 후보).
	- kis-data-hub: 연장세션 현재가(NXT 포함) 제공.
	- tvr: 세션 캘린더 게이트.

- FR-4: 인스턴스 부분 장애 시 해당 인스턴스 슬롯만 스킵(degraded 기록), 나머지 정상 진행. 전 인스턴스 장애 시 cycle degraded_hold.
- FR-5: 멱등 intent_id에 인스턴스 식별 포함(중복·오라우팅 방지).
- FR-6 (trex-core, 별도 REQ): KIS 주문 거래소구분(NXT/SOR) 지원.
- FR-7 (kdh, 별도 REQ): 연장세션(NXT 포함) 현재가 제공.

# 6. 리스크/가정 목록

## 리스크
- R-1 (High): **NXT 스택 부재** — trex-core 주문·kdh 시세 모두 신규 개발이며, 특히 **trex-core 브로커는 라이브 주문 경로**라 변경 위험 큼(orb/tsl 회귀).
	- 완화 방안: KIS 스펙 조사 선행(OQ-1) → 거래소구분을 **opt-in 파라미터**(기본 KRX, 미지정 시 기존과 byte-동일)로 additive 설계 + 고위험 batch로 QC 강화. tvr 외 데몬 무영향 검증.
- R-2 (High): 연장세션 유동성 얇음 → 밴드 트리거가 나쁜 가격에 체결(스프레드·임팩트). 특히 프리마켓.
	- 완화 방안: NFR-1 보호장치 설계 + 초기 운영은 관찰 모드(연장세션 체결 로그 검토) 후 확대. 필요 시 세션별 밴드 가중.
- R-3 (Medium): 팬-인 복잡도 — 라우팅 오류 시 잘못된 인스턴스로 주문.
	- 완화 방안: row 태깅·intent_id 인스턴스 포함·라우팅 단위 테스트 + 인스턴스별 큐 이름 규약 고정.
- R-4 (Medium): NXT 휴장/세션 캘린더 오류 → 체결 불가 시간 주문 발신(거부 누적).
	- 완화 방안: 세션 캘린더 단일 소스(kdh holiday-check 확장 여부 OQ-3) + 거부 시 무해(재시도 없음, 다음 cycle 재수렴).
